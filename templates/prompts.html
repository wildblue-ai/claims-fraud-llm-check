Logic in this system

Every piece of decision-making in this POC is either a deterministic rule or an LLM prompt. The split is deliberate — rules for the gate, LLMs for the triage — and it's the product-strategy argument for how LLMs fit into regulated-industry workflows. Both are shown below so a reviewer can audit the full chain.

Why this is a rule, not a prompt
In a regulated industry, the "flag or don't flag" decision has to be replayable on an audit cycle without re-validating model behavior. Deterministic code meets that bar; an LLM doesn't. The LLM's job is the narrative triage that happens after the rule fires (see Prompt #4 below) — not the flag decision itself.
How it scores
  1. For each provider, compute their premium_progressive rate (share of that provider's claims that are premium progressive).
  2. Compute the population mean and standard deviation of that rate across all providers.
  3. For each provider, compute a z-score: z = (rate − mean) / stdev.
  4. A provider is flagged if z > threshold (configured at 2.0σ). All their claims inherit the flag.
  5. risk_score = z × 25, clamped to [0, 100].
Scoring function (from detection.py)
def score(claims, threshold):
    # Per-provider premium_progressive rate
    totals, premium = defaultdict(int), defaultdict(int)
    for c in claims:
        totals[c["provider_id"]] += 1
        if c["lens_type"] == "premium_progressive":
            premium[c["provider_id"]] += 1

    rates = {pid: premium[pid] / totals[pid] for pid in totals}
    mean  = statistics.fmean(rates.values())
    stdev = statistics.pstdev(rates.values())

    triggered_providers = set()
    for pid, rate in rates.items():
        z = (rate - mean) / stdev
        if z > threshold:             # threshold = 2.0
            triggered_providers.add(pid)

    for c in claims:
        pid = c["provider_id"]
        z = (rates[pid] - mean) / stdev
        c["risk_score"]   = max(0, min(100, z * 25))
        c["triggered"]    = pid in triggered_providers
        c["triggered_rule"] = "provider_upcoding" if c["triggered"] else None
        c["rule_reason"]  = (
            f"Provider {pid} bills premium_progressive at {rates[pid]*100:.0f}% "
            f"vs population mean of {mean*100:.0f}% (z={z:.1f})"
        ) if c["triggered"] else None
    return claims
How threshold was chosen: Phase 2 of the build dispatched a subagent with prompts/phase-2-detect.md — a pass condition of recall ≥ 0.70 on the seeded fraud labels, a retry budget of 3, and a tuning knob for the threshold (allowed range 1.5–2.5σ). Baseline 2.0σ passed on the first attempt at recall=1.00, precision=0.57. See the Flow page for the agent-driven build.
